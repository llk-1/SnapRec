## 实际应用进程采集

直接启动通用 Debug 应用，已有屏幕和麦克风授权。Debug 专用检查使用实际 `AppState`、录制协调器、ScreenCaptureKit 引擎和文件服务，按顺序执行 6 次短录制。系统测试音由独立的 QuickTime Player 播放，麦克风使用已授权的系统默认输入。最终结果见 [native-smoke.json](../build/native-smoke.json)，**6 次采集和 1 项完成预览检查全部通过**。

所有文件都有 H.264 视频、正时长及可读取的完整 MP4；文件服务在原生完成回调后验证并发布。声音场景具有可解码的非零音频采样。双路场景输出 1 条原生混合音轨，不能从音轨数量独立证明每路声音的可听性。

区域输出验证了本机 2 倍 Retina 缩放。窗口场景使用 `desktopIndependentWindow`，目标被不透明红色窗口覆盖，输出中心仍为绿色，验证独立窗口捕获而非桌面矩形截图。此检查通过公开 API 构造自有测试窗口的过滤器；系统单窗口选择器的用户选择流程仍需人工验收。

最终完成窗口的实际 AppKit 视图树包含 `AVPlayerView`。早期运行暴露出本机 SwiftUI `VideoPlayer` 的运行时类型解析崩溃，已替换为直接嵌入 AVKit `AVPlayerView`，之后连续 6 次实际完成预览及独立回归测试通过。

普通 Launch Services 启动的应用与终端启动的已授权调试进程权限不同。交付应用自身尚未获得全局屏幕授权；普通启动后实际触发区域录制，正确显示权限拒绝提示、系统设置入口和重启说明，没有开始采集或崩溃。没有替用户授予权限。用户需按 README 给同一个应用副本授权后再录制。

该权限错误窗口曾被 SwiftUI 自动尺寸计算撑高，已明确让 AppKit 管理窗口大小；普通启动下的错误窗口截图回归确认尺寸正常。最终常规测试和通用编译已在这次布局修正后重新通过。测试中临时打开的麦克风已恢复默认 Off，退出并重启后实际确认仍为 Off。

实际 `full-both` MP4 已在 QuickTime Player 中打开并启动播放，播放器识别 2 秒时长并渲染实际录像画面。音频已通过 AVFoundation 解码检查；未进行可辨识麦克风人声和两个独立声音来源的人工试听，不能将“能播放”和“非零 RMS”写成双路试听通过。

早期单次全屏 UI 录制也保存了约 77.8 秒、2940 × 1912 的视频。第一次音频源是同一调试负责进程下的 `afplay`，被自身音频排除，音轨为静音；没有把它计入系统声音通过。改用独立 QuickTime Player 后取得上述非零音频结果。

## 人工测试步骤与未执行项

1. 正常启动应用，检查菜单栏图标和录制菜单；关闭所有普通窗口，确认菜单栏继续运行。录制中从菜单栏停止，再测试录制中 Quit 是否先封装视频。
2. 全屏模式选择每一块显示器。区域模式在每一块显示器拖动选区，检查尺寸提示、松手启动、Esc 取消；包括负坐标排列和不同缩放比例。当前机器没有多显示器组合测试条件。
3. 从系统窗口选择器选择其他应用窗口，移动并遮挡它；播放该应用及另一个应用的声音，验证只有目标应用声音进入窗口录像。该应用其他窗口声音也可能录入，是产品规定的范围。
4. 分别检查 3 秒、5 秒和关闭倒计时；取消倒计时后立即开始新录制，重复点击开始和停止。
5. 用耳机播放清晰测试音，同时通过麦克风说出可辨识内容。分别录制仅系统、仅麦克风、双路、静音组合，在 QuickTime 中逐个试听。双路必须能区分两个来源，不能只检查有音轨。
6. 通过系统设置拒绝屏幕或麦克风授权，验证提示、设置入口及重新启动说明；只由用户更改权限，不由测试代码自动重置 TCC。
7. 在设置中逐项修改并重启应用；断开指定麦克风，再开始录制，确认提示重新选择。检查 60 FPS、1080p、光标开关和完成后打开文件夹。
8. 使用不可写目标目录或空间受限的测试卷验证错误、保留文件及 Save Elsewhere。不要为测试耗尽系统卷空间。录制中关闭目标窗口、断开显示器或麦克风，确认异常不显示为普通成功。
9. 在 macOS 15 实机与 Intel Mac 运行相同场景；执行长时间录制，观察 CPU、内存、UI 响应和结束后的资源释放。
